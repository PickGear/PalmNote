PalmNote Version History
========================

Release history of PalmNote (newest version first; entries marked beta are pre-release).

1.4.3-beta2 (2026-11-03)
------------------------

About
- This is 1.4.3 beta2 (development build, not yet released): adds demo mode and portable backup keys, lets the vault turn off password protection and favorite entries, and removes clipboard auto-clear

Added
- Demo mode (sandbox): try the app with sample data and jot down your own entries; closing it clears the samples, and anything you recorded can move back to your real books
- Self-contained portable backup keys: backup packages now carry the database key, so restoring on a new phone, after a reinstall, or on any device just works; an optional backup password encrypts the whole package
- Vault: turn off password protection (verify once, then switch to password-free entry with every entry kept); favorite entries, pinned to the top in lists and category filters
- Vault detail page: the password auto-hides after 30 seconds; leaving the editor now asks about unsaved changes
- Vault settings: a new read-only "lock timing" row (follows the global app lock)
- Dashboard net-worth card: an amount privacy toggle — hide amounts, income/expense and trend direction at once
- Asset grid cards: two styles (large / small image), switched in Settings with instant effect
- Asset distribution card pagination rework: fade bands while sliding and an entrance animation
- Versioned exchange-package format: a self-describing manifest inside the package; imports negotiate by version
- The in-app version history is now available in English (follows the app language)

Fixed
- Fixed the bottom bar not returning Home after entering Bills from a dashboard card
- Fixed editing a sample row in demo mode moving it out of the sample set
- Fixed misaligned two-column inputs in the asset form on the English UI
- Fixed vault search missing note content
- Fixed leftover avatar image files after resetting the vault
- Fixed the eye icon in vault details not following the plaintext state
- Fixed rejected legacy backup restores not explaining the real reason
- Fixed a wrong backup password being swallowed and reported as file corruption

Changed
- Backup and import/export pages redesigned: summary card + sectioned row layout
- Settings card row heights unified to 56 / 72 dp
- Removed vault "clipboard auto-clear": the system blocks clipboard reads in the background and IME clipboard history cannot be cleared, so the promise could not be kept; copying still marks content as sensitive and the system clipboard overlay hides previews
- Vault copy now says "password" everywhere (no more "master password")
- The widget picker top bar is unified with the rest of the app
- Demo sample data replaced with neutral samples; sample images converted to WebP, package about 1.5 MB smaller

About

Fixed
- Missing divider between the last two rows in bill details
- The bills page not defaulting to today (including the week view sticking to the last week of the previous month)
- Asset usage records: the "N times" count not falling back after a deletion and single-use cost distortion
- A grayish sheet background on the add-asset dialog
- The asset details "usage records" empty state taking most of the screen
- Secondary-page top bar backgrounds inconsistent with other pages
- Habit details: the milestone celebration card squeezed off screen and the focus timer ring lagging behind the readout
- Jank in category details when checking off or collapsing sections
- The pending-reimbursement card showing only the current book: no more unrelated entries from other books (reimbursement management still shows all)

Improved
- The asset summary card collapses with your finger: drag the card or scroll the list to collapse/expand; it snaps into place on release and remembers the state
- Dashboard cards: long-press and drag to reorder, with auto-scroll at the screen edges; returning from other tabs fades the page in as a whole
- Secondary pages now push in from the right and slide out to the right on back
- Cold start drops the skeleton screen; the top bar shows while loading

- Daily receipt paper: warm white stock, a scalloped tear edge and thermal texture; the itemized style became a table (time / category / amount columns, the note under the category and the wallet under the amount); the barcode is now a scannable EAN-13 (the number is the print time)

1.3.0 (2026-08-11)
------------------

Added
- Vault module (feature/vault): a fully offline password manager with field-level AES-256-GCM encryption and its own master password (key-wrapping — changing the PIN never re-encrypts entries)
- Vault: list / search / category filters, masked detail viewing (👁 toggle), CRUD, a password generator (length + character sets + entropy) and one-tap copy with 30-second clipboard auto-clear (hash-tracked, never clears your own copies)
- Vault entries gained a phone field (plaintext, same rules as email, searchable); the vault database went v3 → v4 (MigrationV3ToV4)
- Vault security: biometric unlock (a non-exportable Keystore key wrapping the data key + BiometricPrompt / CryptoObject), a no-lock mode (skip the password; the data key is wrapped by a non-authenticated Keystore key and can be upgraded to PIN / biometrics anytime), configurable auto-lock (immediately / follow system lock / 5-minute timeout, default follows the system), 5 failed attempts lock for 30 seconds (brute-force protection via LockoutTracker), configurable require-auth and a full reset
- Vault entry points: a dashboard card (shows only entry counts, titles hidden for privacy, old card configs merged automatically) and settings entries (clipboard clear / require auth / entry count / change master password / reset)
- Database v4 → v5: the vault_entries table (Migration4To5)
- Database encryption with SQLCipher: full-database encryption (net.zetetic:sqlcipher-android) wired through Room via EncryptedOpenHelperFactory with automatic plaintext migration; the database key is wrapped by Android Keystore (AES-256-GCM, computed inside the TEE, non-exportable) and stored in SharedPreferences (backups can carry a portable key for cross-device restore)
- OCR engine swap: ML Kit's closed model → an in-house OcrEngine interface + PaddleOCR PP-OCRv6 (the ppocr-sdk module, offline inference on ONNX Runtime, models bundled in assets); ML Kit and coroutines-play-services dependencies removed
- APK size optimization: release ships only arm64-v8a + onnxruntime-mobile, ~86 MB down to ~42.6 MB (later reverted to full onnxruntime-android 1.21.1 because the mobile operator set could not run the PP-OCRv6 model)
- Tests: VaultCryptoTest (encryption round-trips / tamper detection / key derivation), VaultPasswordGeneratorTest and Migration4To5Test; unit tests 75 → 150 (including 6 Room migration tests)
- Migration3To4
- BillRepository.getBillsByDateRange

Changed
- Amounts migrated from Double (yuan) to Long (fen): exact integer math across bills / wallets / budgets / assets / recurring templates / plan lists, ending floating-point drift
- A Money value type (domain/model/Money.kt) and per-currency CurrencyUtils formatting
- Database v3 → v4: migration rebuilt the amount tables with a ×100 conversion (including existing data)
- Full v1 → v5 migration regression (MIGRATION_1_2 / 2_3 / 3_4 / 4_5 registered)
- Database v5 → v6: vault data moved out of the main database into palmnote_vault.db (Migration5To6, best-effort copy then drop); v6 → v7 removed the unused timeOfDay column from bills / bills_recycle_bin (Migration6To7); the main database is now v7
- CI: lintDebug (abortOnError), testDebugUnitTest (including Room migration tests) and Room schema checks
- CI: migration tests moved to Robolectric on the JVM (the free runner has no KVM and the emulator hangs); parallelized into quality / build jobs with one Gradle call each, reusing the build cache across jobs
- lint.abortOnError false → true
- detekt baseline regenerated: existing UI debt frozen (LifeScreen / BillDao / ReportScreen)
- Two-module architecture: core split out (namespace com.palmnote — data / domain / shared UI / resources / AppDatabase schema) alongside app (namespace com.palmnote.app — business UI / backup / workers / vault); the empty feature module removed; the AppDatabase schema moved to core/schemas (v1–v7) and VaultDatabase stays in app/schemas (v1–v4)
- CurrencyUtils dropped the global-context anti-pattern: the context-free overload and AppContextHolder are gone and every call site passes a context explicitly (Composables use LocalContext.current, ViewModels inject @ApplicationContext)
- 55 string keys referenced by both core and app are declared per module (AGP R classes are per-module), with core's missing keys migrated too

Fixed
- Critical: the v2→v3 migration's index names didn't match the entity-generated names, crashing every upgrade (idx_bills_* → index_bills_*)
- WeChat CSV imports not stripping minus signs, which could pollute the books with negative amounts
- The daily "not recorded yet" reminder misfiring: exact timestamp matching became a same-day range match
- Positive-day / countdown / birthday / anniversary off-by-one: epoch/86400000 (UTC) replaced with system-timezone date conversion
- Feb-29 birthdays / anniversaries: a duplicated call in the withYear catch caused a second crash
- Subscription reminders: the 31st falls back to the month's last day in short months; lastBilledDate is written back to prevent repeats
- Date format internationalization: mismatched parameter types between locales in date_format_weekday_full etc. (lint StringFormatMatches)
- Backups didn't include the app lock's SharedPreferences: after a restore the old SHA-256 PIN couldn't verify because the salt reset, locking users out of their data
- No WAL checkpoint before backup: -wal/-shm could disagree with the main file and corrupt a restore; it now checkpoints first and copies a consistent snapshot
- getExternalFilesDir can return null and NPE'd the backup; an internal-storage fallback was added
- The settings page showed v1.0.0 instead of v1.2.0 (now consistent with app_version)
- detekt config: outdated ComplexMethod / TooManyFunctions rule names broke the task
- Dead code cleanup (unused DAO methods / classes)
- The today's-to-do entry point was broken
- Bill list queries gained indexes (index_bills_*)
- The report page lacked a loading state (flashed blank on first load)

Security
- System backup disabled (allowBackup=false): prevents the plaintext database (including the PIN hash) from being backed up to Google's cloud
- FLAG_SECURE while the app lock is on: no screenshots or recent-apps thumbnails of financial data
- Lockout state persisted: failure counts and lockout duration live in SharedPreferences — killing the process cannot bypass brute-force protection
- PBKDF2 iterations unified at 25k for the app lock and the vault, balancing unlock latency against brute-force cost (old SHA-256 PINs migrated automatically)
- PIN verification / setup moved to the IO thread so PBKDF2 no longer blocks the main thread
