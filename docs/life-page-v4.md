## 一、为什么推翻 §15.1

§15.1 的骨架是：`TopAppBar → 问候区 → 概览区(3卡) → 通知区 → 动态分类区(可折叠 Section) → FAB(8项)`。

它已经解决了**层级**（轻/中/重三段），但有一个结构性缺陷：

**它是一列纵向区块。** 所有内容在同一条纵轴上排队，用户永远在"往下滚"，永远看不到全局。三卡、通知、四个折叠 Section —— 一屏只能装下前两个。

对标后发现：**八家产品里没有一家用"一列区块"承载生活类首页**。它们要么是**一块板**（Streaks 圆环网格、Grid Diary 九宫格、Bento），要么是**一条轴**（Structured 时间轴），而且**都带视图切换**。

所以 v4 推翻的不是配色也不是分区，是**"一列区块"这个骨架本身**。

## 二、对标：八家各取一条可落地的手法

只取手法，不取风格。每条都注明落在 v4 的哪一处。

| 来源 | 取的手法 | 落在 v4 |
|---|---|---|
| **Structured**（日计划） | 一天是一块可切换视图的对象：长按时间轴切 日/周/月 | §三 顶栏三视图 |

| **Gentler Streak** | **首页随时间变化**：早上以健康摘要为主，白天记了活动则活动占据主位 | §四 时间三态 |

| 视图 | 回答的问题 | 内容 |

- 目标 → 跨期累积 → 属于"全部"（按进度看）和"今天"（今天的推进）

## 四、「今天」视图：会呼吸的格子板 ⛔ 已回退（v1.40）

### 4.1 布局规则（硬约束）

基于 **3 列网格**。格子跨列数 **五档**（⚠️ v1.2 由四档扩为五档，**新增 XL**，规格见总纲 §4.3）：

| 档位 | 跨列 × 跨行 | 面积单元 | 角色 |
|---|---|---|---|
| **XS** | 1 × 1 | 1 | 指标快照 |
| **S** | 2 × 1 或 1 × 2 | 2 | 指标 + 一行说明 |
| **L** | 3 × 1（高 36dp 即邀请条） | 3 | 全宽窄条 |
| **M** | 2 × 2 | 4 | 主角格（**默认档**） |
| **XL** | 3 × 2 | 6 | 主角加强档 |

**为什么要加 XL**：原四档里最大的正好是 2×2，而用户明确要求「主卡片今天要做什么……**只能大了**」——四档没有「更大」可选。

**一屏的视觉层级仍然成立，但落法改了**（⚠️ v1.2 修订）：**大格（M / XL）上限 2 张，只有第一张是主角**（`ModuleLife #C2185B` 描边），第二张用普通描边。原「一屏之内只能有一个主角格」是**硬唯一**，会在用户拖第二张大格时频繁触发自动降级——**悄悄改用户排好的东西，比不允许更糟**。「3 个等宽卡 = 没有主角」这条判断仍然有效，只是改由**档位差**而非**数量唯一**来兑现。

⚠️ **不是每一档都对每张卡开放**：尺寸由**功能**决定（总纲 §4.3 能力矩阵）。例：**「今天要做什么」只有 M 与 XL**——至少要放 2 行清单，且每行要 48dp 触达。不受支持的档位在选择器里**不出现，不是灰掉**。

**「位置锚定」降级为「默认布局的性质」**（⚠️ v1.2 修订）：**默认布局**里每个分类位置固定（今天左上、打卡右上、待办右中、存钱/纪念下排），新用户不会找不到东西；但用户进入编辑模式后**可以拖排序、改尺寸**，并可存成自定义布局（总纲 §4.4）。⟹ 原句「只允许尺寸呼吸」是**默认态的描述**，不再是全局铁律。

### 4.2 时间三态（记忆点所在）

格子板的**主角格**随一天的时间与内容移动：

| 时段 | 主角格 | 触发条件 | 兜底 |
|---|---|---|---|
| 早晨 05:00–11:00 | **今天要做什么**（待办清单，可就地勾选） | 存在今天的待办 | 无待办时，主角格 = 今天（问候 + 简述） |
| 白天 11:00–19:00 | **今天记了什么**（最近记录 + 缩略图） | 今天已有记录 | 无记录时，回退为「今天要做什么」 |
| 夜晚 19:00–05:00 | **今天怎么样**（心情 + 一句概览 + 连续天数） | 恒定 | — |

**内容优先于时段**：时段只决定"默认给谁"，一旦当天有记录，记录立刻抢到主角位。这就是 Gentler Streak 的做法——首页不固定，按你当下最相关的信息让位。

**时段角标**（v1.31）：主角格角落一枚 **9.5sp 灰字角标**（早晨 / 白天 / 夜晚）。三态是**自动切换**
的，没有角标用户只会看到「主角莫名其妙变了」—— 角标把机制变成可见的。**位置恒为格子右上角**
（v1.33 统一：曾出现 home_1 右下 / home_2 右上不一致；home_1 的「2 / 3」气泡挪到与标题同行让位）。

### 4.3 空状态 = 邀请条（Grid Diary 的借鉴）

空分类**不隐藏、不折叠成标题行**，而是压成一条**虚线邀请条**：

```
┌────────────────────────────────────────┐
│ 还没写日记                    记一条 →  │   ← 虚线描边，36dp
└────────────────────────────────────────┘
```

理由：Grid Diary 证明了「空格子比空白页更想让人填」。§15.1 原文写的是"折叠显示分类标题+模板图标摘要"——那是**收纳**，不是**邀请**。收纳让人忘记它存在，邀请让人想点。

**邀请条的顺序按"该时段该做什么"排**：早晨第一条是"还没写今日待办"，白天是"还没记心情"，夜晚是"说一句今天"。

### 4.4 格子可换、可拖、可缩放（Apple Health 的借鉴，⚠️ v1.2 扩充）

原设计只写到「**配角格内容可长按替换**」。**v1.2 把这一条扩成统一的编辑模式**（用户要求「自由切换形态大小 + 自由搭配 + 保存布局」）：

长按格子板空白处 → 所有格子出现拖拽手柄与**尺寸角标**；拖动改顺序、点角标改档位（**只列该卡允许的档位**）；退出时可「保存为新布局 / 覆盖当前布局 / 放弃」。**手势沿用既有的长按，不新增手势。**

**入口可发现性（v1.32）**：长按空白处是**快捷方式**，但没有任何提示 = 用户永远不知道能编辑。
补**第二入口**：FAB 弹窗**工具行「编辑布局」**（与「模板管理」并列，§7.1 同步）——
用现成容器解决，不加新控件、不加新手势。

候选内容来自该分类下的模板：打卡率 / 待办数 / 存钱进度 / 专注时长 / 纪念天数 / 订阅支出。默认按使用频率排前三。

**落地零新概念**：`LifeHomeCardConfig` 已经存在（`LifeHomeCardType` + `visible`），只需**扩三键**——`order: Int` / `span: String?` / `customColor: String?`（`customColor` 对齐 `DashboardCardConfig.kt:25` 的既有字段）。这是**延长既有结构**，不是新增体系。完整规格见总纲 **§4.3 / §4.4 / §4.5**。

**多实例模板的呈现归总纲 §4.6。** 同一个模板有多个实例时（例如 3 个存钱目标：买房 / 旅行 / 应急），**卡片锚在模板上、不锚在实例上——同一个模板永远只占 1 格。** 理由不是偏好，是面积预算：一实例一卡按生活常识估计就是 **23 单元 / 18 张**，而一屏预算只有 **12 单元 / 8 张**（超 1.9 倍）；而且它会让布局在增删实例时留下空洞、让同模板多张卡同色（＝ §11.2 否过的观感）。集合型模板的四档呈现（XS / S / L / M）、首显规则，与**两条禁令（不自动轮播、不为实例单独开格）**见总纲 **§4.6**。

### 4.5 提醒不再是独立区块

§15.1 有独立的**通知区**。v4 **取消这个区块**，理由是：

- 独立通知区在"没有提醒时"是空白，在"有提醒时"是**第四个区块**——而它承载的信息（订阅到期、生日临近、纪念日临近）**本来就有归属的格子**。
- 改为：**让对应格子自己变色 + 顶栏的一句提醒**。
  - 生日 3 天内 → 纪念格描边转 `Warning #E8B94A`，显示"还有 3 天"
  - 订阅 7 天内到期 → 订阅格同理
  - ⚠️ **v1.30 修订（2026-09-22）**：那句提醒落在**顶栏胶囊行、标题旁**的警示 chip（整句
    「生日还有 3 天」，9.5sp 紧凑化），**仅标题「生活」态显示** —— 标题单击到日期态时 chip 让位

### 5.1 存储层结论：**不需要 v9**

已核实：

- `LifeItem.createdAt: Long` 是**普通整数列**（非 JSON），`dueDate: Long?` 是 v8 执行列。
- `LifeItemDao` 已有 `getDistinctDueDatesBetween(start, end)` / `getScheduledBetween` / `getOverdue` 等同族按时间查询。
- **缺的只有一条按天分组计数**，照抄既有模式即可：

```sql
SELECT date(createdAt / 1000, 'unixepoch', 'localtime') AS day, COUNT(*)
FROM life_items WHERE createdAt BETWEEN :start AND :end GROUP BY day
```

用 `'localtime'` 而非 `createdAt / 86400000`，否则跨时区会把记录算到前一天。

**⟹ 日历视图 = 新增 1 条 DAO 查询 + 月格 UI，零迁移、零回填风险。** 这是 v4 里性价比最高的一块。

### 9.3 ✅ 进度规格已定稿：形态族（2026-09-20 六次更新，末次为定稿）

**格子板里会出现至少 3 处进度显示**（打卡格、存钱格、卡片流）。而 §3.5 查出「进度在本仓库有四套互不相同的外观」。

**最终定稿在 `life-refactor-master-plan.md` §3.5.1**（注意**不是 §3.6**，§3.6 是「两条可验收的硬指标」）：

- **形态不是一个，是一族（两族 11 种），按语义选**。**A 横向族**：① 梳齿波形（分布）· ② 节点轨道（阶段）· ③ 厚胶囊（单一目标）· ④ 细轨 + 端锚点（区间）· ⑤ 分组点阵（配额）；**B 圆环族**：⑥ 厚环闭环（重量）· ⑦ 缺口仪表（量程）· ⑧ 同心双环（对照）· ⑨ 细环巨数（留白）· ⑩ 分段齿环（离散）· ⑪ 环上珠子（叙事）。
- **P1 能用的不是一种，是五种**：③ 厚胶囊与圆环族的 **⑥⑨⑩⑪ 都只要 `calcProgress()` 现有的 `0~1`**（环本身只需比例，只有端标才需要 `cur`/`tot` 原值）；① 需要按天聚合（与 §6.2 日历视图同一条查询）；②④⑤⑦⑧ 待 P4 字段就绪。选型表见 §3.5.1 §一 与 §一·B。
- **横向读「还剩多少」，圆环读「完成到什么程度」**：长度天然线性可估（还差 ¥6,800、还有 12 天）；角度天然表示占比（存钱状态、打卡率）。**同一字段不得同时用两种。**
- **比例优先于层次**（全族共用）：条厚 = 卡宽 10%（**厚档 33dp** / 薄档 12dp / 分段档 14dp），**只用两色**，**值 ∶ 标签 ≥ 3×**。层数不是精致，比例才是。
- **分档（2026-09-20 新增，现为形态族里的 ③④⑤）**：厚档（详情 / 重点卡，33dp，**无行进物**）· 薄档（列表 / 卡片流，12dp + 行进物）· 分段档（打卡 x·y，8 格 + 行进物）。**厚度与行进物互补而非叠加；分段与厚度二选一。**
- **环回归**（2026-09-20 第六次修订）：上一版「环降级为动作靶」的依据是「参考图里没有环」——**该依据已证伪**（用户随后明确要求要圆环）。**规则 1 恢复生效并改写为「一个字段只有一种进度渲染」**，形态由**字段语义**选定**默认值**、全局一致。（2026-09-20 **v1.8 补**：用户可在**模板编排器**里按字段改形态，值存在 `FieldConfig.progressStyle` 上——**改完仍是「一个字段一种」**；卡片/详情页**不给**换形态入口。详见总纲 §4.2。）
- 34dp 的环**仍是「点一下就完成的动作靶」**（本文件 §4 的打卡手势）——那是**动作**，不是进度；与进度环并存但**不得混用**。
- ⚠️ **列表卡不得用圆环**：环径 **< 110dp 时环心放不下 ≥11sp 的数字**，而列表卡放不下 110dp 的环。⟹ **列表卡一律走 A 横向族（薄档），圆环只用于重点卡与详情页。**
- **形态默认值由语义给、用户可改（v1.8）**：字段落在模板里时形态 = 语义推导结果并标「推荐」；要改才展开选择器（默认折叠，**常规用户不会接触到「11 种形态」这个概念**）。**算不出来的形态不出现在选项里**。若用户给列表卡字段选了圆环，**自动投影为横向档并提示，不阻断**。**形态存在字段上、不写在模板里**，所以同一字段在任何界面仍只有一种渲染。
- **尺寸**：**A 横向族三档** —— L 详情/重点卡 **33dp** · M 列表卡 12dp · M 分段档 14dp · S 桌面小组件 5dp（②④① 见 §3.5.1「十一形态尺寸表 · A」）。**B 圆环族** —— 环径 **170dp**（厚环 / 缺口 / 同心 / 珠环）· **166dp**（分段齿环）· **150dp**（细环）；环宽 **26dp**（厚环）· **14dp**（齿环）· **7dp**（细环）（见 §3.5.1「十一形态尺寸表 · B」）。
- ⑧ 同心双环**必须配图例**（两圈不自解释）；⑦ 缺口仪表的两端锚点**只在有起止语义时出现**。

⟹ **本文件早期画的「细条 3dp / 圆角 2dp」、「六层精致」全部作废；「唯一形态」这一提法同样作废。** ⚠️ 但 **v1.4 的「环形仪表」与 56dp 下限要分两步读**：作为**唯一载体**被否是对的；作为**候选形态之一**是对的——它现在就是 **⑥ 厚环闭环**（下限改为 **110dp**，因环心要塞 ≥11sp 的数字，见 §一·B）。实现时不得自造新外观，一律调用 §3.5.1 的组件——**十一种形态是组件入口的参数，不是十一份规格**（底座、双色调、圆头端帽、排印共用一套）。

⚠️ 与 §9.2 的「格子圆角 16dp」不冲突：那条说的是**卡片**圆角，本节说的是**进度部件**的内部规格。
