# 桌面小组件 · 实现说明

> **分工**：视觉与尺寸口径（布局、Token、圆角、尺寸声明、预览分层）见同目录 `spec.html`；本文只记**实现机制**——色板与不透明度、色调自适应、深链与配置、pin 流程、命名口径。
> 两份文档冲突时，以 `spec.html` 为准。


十个组件（账单 / 待办 / 计数 / 物品 / 净值 / 订阅 / 概览 / 打卡 / 快捷入口 / 接下来）统一走 v37 设计语言（视觉口径见 `spec.html`），本文记录其实现约定与机制。组件清单与布局以 `ui/widget/` 与 `res/layout/widget_*.xml` 为准。

> 2026-10-23 用户定：**密码本不提供小组件**（高危隐私，不上桌面），其形态、布局、预览与深链已整体下线。

## 设计语言

- **圆角卡片**：统一卡片底（`widget_layout` 根节点），底色与**不透明度**逐实例可调。
  不透明度只作用在**背景层**（卡底、会盖住整卡的色砖），文字 / 图标 / 进度值 / 语义色
  （逾期红、色族强调色）保持实色；100% = 完全不透明、20% = 几乎全透。
  **内层面板不再单独乘一次不透明度**，而是「卡底 + 极淡覆盖层」：深色卡叠 6% 白、浅色卡叠 6% 黑
  （`WidgetToneSweep.SURFACE_OVERLAY_ALPHA`）。半透明卡底上再叠一层半透明面板会越叠越深，
  50% 黑底在浅壁纸上就成了「浅灰卡边 + 深灰面板」—— 面板只比卡底差一档，才不会割裂。
- **内容配色随背景明暗自适应**：实例接管了背景（自定义纯色 / 图片）时按背景明暗选 `WidgetTone`
  （塞进 `WidgetToneContext`），布局里写死的令牌由 `WidgetToneSweep` 按 id 改写。所以布局里写死
  令牌的 view **必须有 id**（`WidgetToneSweepTest` 从 XML 侧交叉核对），否则它在深色自定义底上
  永远跟着启动器的明暗走。
  自动判定是**一刀切**规则（用户 2026-10-20 定）：**白底用深色字，其他任何背景色都用浅色字**
   —— 饱和色（青 `#0891B2`、橙 `#FF8A3D`）配白字才符合观感，只有白底例外；判定只看背景色本身，
   与不透明度无关。
- **六族色**：各组件的强调元素（徽标、色点、占比条段）取 `WidgetData.colorFamily` 的同族色，运行时按当前主题包取色，亮暗两套。
- **强调色逐实例覆盖**：配置页可选「跟随应用」或强制某个主题包的主色，只影响该组件（`widgetAccentThemeFor`），跟随主题色的组件（账单 / 概览 / 接下来）生效。
- **文字层级**：主数值 / 标题用主文字色，次要说明用 `widget_v2_text_secondary`；深色模式走 `values-night` 令牌。
- **金额折叠**：大数按万 / k·M 紧凑格式，溢出 ellipsize 兜底。
- **无障碍**：动态行与快捷 chip 均带 contentDescription；选择器 40 个 info 描述齐全（`res/xml/*_info.xml`）。

## 「接下来」焦点卡

一张卡只显示当前最该处理的一件事，候选按序取第一个：今天到期未完成待办（卡上直接勾）→ 3 天内要扣费的订阅（金额 + 扣费日）→ 最近的倒数事件。底层一变，数据变更刷新链路自动把卡切到下一件，无需任何配置。

## 一个组件、多套尺寸：按族收敛

v37 起每个组件族固定四档（4×2 / 2×2 / 4×1 / 4×4），同一族的不同尺寸是**不同 provider**，
目录里靠 `titleRes` 折叠成一张卡，点进去在弹窗里左右翻着选（`WidgetPin.CatalogComponent.entries`，
页序按 4×2 → 2×2 → 4×1 → 4×4）。此前 v22 的「本月记账 三套样式（数据 / 柱状 / 预算）」已下线，
`BillTrendWidgetProvider` / `BillBudgetWidgetProvider` 不再存在，见 `WidgetPin.entries` 的 40 个形态。

两条取数规则容易踩错，都写在 `fetchSnapshot` 里：

- **预算表没有账本维度**：实例选了某个账本时 `budget` 置空，否则会拿 A 账本的支出除以全账本预算。
- **最高分类与预算解耦**：只要本月有支出就查，不挂在「有没有设预算」下面 —— 挂上去会让没设预算
  的用户永远看不到这一行（柱状版 4×4 的第三格还会恒为 `--`）。
- **近 7 天的账本口径在 SQL 里带**（`getDailyExpenseSinceByBook`）：不能拿「该账本当月账单的日期集合」
  去过滤全账本的日聚合，跨月时上月那几天会被清零、有记录的那天又用了全账本合计。

## 尺寸分档（响应式）

- **目录里只做四档**（v37 收敛）：`4×2 / 2×2 / 4×1 / 4×4`，见 `WidgetSizeClass`。
  其余尺寸由桌面自由拖拽，组件按**宽高阈值**归到相邻一档重排（不用最近邻：旧版桌面给的
  「横屏最宽 × 竖屏最高」组合会让最近邻跳到对角档）。归并只有一处，别在每个 provider 里各写一套 if。
- 组件尺寸读取走 `sizedRemoteViews`：Android 12+ 用 exact sizes 多份布局，旧版按 min/max 取两档。
- **高度 < 160dp（不足 2 格）收起次要元素**：计数组件藏日历条、保留「目标日期」说明行，物品组件藏占比条、色片只留一行。
- **概览有两套版式**：4×3（268dp 起）走 `widget_dashboard_unified` 的 2×2 砖阵；**4×2 及更矮**
  （< 220dp）走 `widget_dashboard_wide`，四块砖并成一行、只留「色点 + 标签 + 数值」，
  用量说明 / 进度计数 / 逾期说明 / 纪念日日期在布局里就设成 `gone`（节点保留，`bindSnapshot`
  按 id 写值，缺 id 会在桌面抛 ActionException）。
- **打卡有两套版式**：4×3 起显示底部三指标；4×2（< 220dp）把 `widget_habit_stats` 整行收起，
  否则最后一行方柱被挤掉。
- 快捷入口宽度 < 110dp（缩到 1×1）时换小卡布局：只留「记一笔」主按钮。
- 计数组件宽度 ≥ 400dp 显示多事件列表，否则只显示最近一个焦点事件。
- `onAppWidgetOptionsChanged` 触发重绑，拖拽改尺寸即时生效。
- 布局里**不能出现 `<Space>` 或 `<View>`**：RemoteViews 白名单只有 Frame/Linear/Relative/Grid
  与 TextView/ImageView 等，真机和 Robolectric 都会抛 `Class not allowed to be inflated`。
  需要弹性占位时用无 `src` 的 `<ImageView layout_weight="1">`。

## 添加页（App 内一键添加）

- 页面底色**不做单独配色**，直接取 `colorScheme.background`（2026-10-21 反馈：此前为贴合参考图铺的
  米色暖底和其它页面并排时明显发暖，已改回；壁纸模式下该色本身透明，直接透出壁纸）。
- 顶部一排**分组 chip**（`全部` + 五个功能分区，`WidgetPin.WidgetGroup`），默认「全部」是纯瀑布流。
  **不插分组标题** —— 标题必须横跨整行，于是每个分区都从新行开始，分区里 2×2 的卡是奇数张时
  右半行就永远空着（实测 10 个组件白扔 2 个卡位 + 5 个标题约 200dp）。分组仍然存在，
  只是从「标题」变成「一次点击」。
- 网格里 4×2 与 2×2 混排时，**把 2×2 的排到一起**（`sortedBy` 稳定排序）：它们占半行，
  夹在两张宽卡之间会让宽卡各留一个洞。
- **入口卡位只有 4×2 与 2×2 两种画布**（2026-10-21 定）：4×2 占满整行、2×2 占一列，
  由 `WidgetPin.entryCellOf` 显式指定（不按宽高比推算 —— 2×1 的 2.16 与 4×2 的 2.30 分不开）。
  排布用 `LazyVerticalGrid` 的混合跨度，**不手工每两个一组**：整行卡会把后面的卡推到下一行，
  手写分行必须自己算余量，组件数一变就错位。
- 入口预览图按**同一画布重出**（`widget_entry_*`，见 `WidgetPreviewPngGenerator.renderEntry`），
  图与卡位同比例才不会留白。不复用 `Entry.previewImageRes` —— 那是各形态自己的画布。
- 入口封面固定挑「最饱满的形态」（`showcaseEntryOf`），不跟随用户上次选的样式。

## 刷新机制

- **数据变更主动刷新**：`WidgetRefreshConsumer` 消费数据事件；备份恢复期间抑制更新（`WidgetUpdateHelper.restoring`）。
- **午夜刷新**：日期敏感组件（待办 / 打卡 / 计数）由 AlarmManager 每日 00:00 触发 `WidgetMidnightReceiver` 重排，开机后 `WidgetBootReceiver` 补排。
- PendingIntent requestCode 按组件分段，避免跨组件互相覆盖。

## 配置与添加

- 系统配置页只碰「跟实例绑定的少数设置」：`WidgetConfigActivity`（概览 / 接下来）改强调色覆盖，
  `BillWidgetConfigActivity`（账单）选账本 + 配色。**不透明度与背景色不在这里**，一律在应用内
  添加 / 编辑面板里改（见下），落桌核对到新实例 id 后写到这个实例上。
- 应用内添加页（`WidgetPinScreen`）按**画廊版式**组织：目录由 `WidgetPin.catalog()` 生成——
  40 个尺寸形态按用途归 5 组、把同基类的形态折叠成一个组件（基类尺寸为默认）。
  页面本身走**中性底**（`surface`，白 / 深色 `#1E1E1E`）+ 二级页顶栏（`SecondaryTopAppBar`，22sp
  黑体）：布局与系统「添加小部件」页一致，但顶栏仍用项目自己的组件，别再造一套。搜索入口与账单 /
  资产各页同款：顶栏只摆搜索图标，点了才换成整行搜索框 + 「取消」，系统返回先退搜索再退页。
  每张卡 = **灰底托就是卡身**（`surfaceVariant` 圆角 22dp，不再套一层白卡）+ 托下**居中**的名称
  （`labelLarge` Medium）+ 一行灰色小字（未落桌写尺寸标 `3×2`，落过桌写「已有 N 个」），
  小字右端一枚「＋」快捷添加（显式 48dp 触控盒；已落桌的组件这里换成「编辑」）——「预览 + 名称 + 一行灰字」就是各家小部件页的样子。
  点卡身弹出**近全高面板**（高度 = 可用高度 × 0.92，`AppBottomSheet(heightFraction=…)` 定住高度后
  内部用 `weight` 分配余量、不滚动，对齐系统「添加小部件」那种整屏悬浮面板）：**顶栏**（左「←」
  + 居中「应用图标 + 应用名」，图标沿用「关于」页那套主色底 + onPrimary 图形）——面板里唯一的
  显式返回入口，与下滑 / 点遮罩 / 系统返回同义；把手传 `COMPACT_DRAG_HANDLE_PADDING` 贴顶
  （M3 默认的 48dp 槽会把顶栏与标题整体压低 24dp，跟系统选择器对不齐；这个参数只组件页传，
  别的面板不受影响）；顶栏下面是名称 + 说明居中一叠（名称 22sp 黑体、就两行，实例数交给画廊卡说）、
  中间是**尺寸翻页器**（`HorizontalPager`：widget 与其下的尺寸分页圆点作为一组居中；圆点行钉在
  面板里固定的一行上，不跟组件或尺寸上下跑 —— 直径 5dp、选中那颗用前景色而非品牌色）——
  **换尺寸就靠滑这一页**：拖动跟手、松手按甩动速度落页、圆点跟着手指连续过渡。尺寸**不再摆一排
  胶囊**（那排胶囊和手势是同一个入口，多一行还得先看字再点），圆点数 = 尺寸个数、是尺寸的
  唯一指示。页高按**全局最大卡**（4×3 = 268dp）算、**不按本组最大** —— 页高就是页内缩放系数的
  分母，按本组最大算的话，矮尺寸组（快捷入口最大 1×1 = 160dp）整组预览只剩真实尺寸的六成，
  而且圆点行会跟着组件上下跑（待办 522dp / 快捷入口 468dp）；按全局算则换页时容器不跳、
  小尺寸在页内居中、圆点行在所有组件里都落在同一行。
  配置区就剩**背景色 + 不透明度**两行：不透明度是**无极滑杆**（`OpacityRow`，0.2–1.0
  连续、右端显示百分比，拖动时预览的卡底与色砖实时跟着变、内层面板始终是卡底上一档淡覆盖层；
  没拖过 = 跟随全局默认、落桌不写覆盖值，拖过就写成该实例的覆盖值）。
  文字颜色没有开关：白底自动用深色字、其他背景色自动用浅色字（见上）。
  按钮钉在底部（50dp 实底胶囊 + 16sp 粗体）；卡上的「＋」不经面板直接按当前
  尺寸落桌（pinSupported=false 或落桌核对期置灰）；已落桌的卡在预览右上角带小勾；搜索按名称与说明
  匹配、名称命中排前并高亮。
- **面板里挑不透明度与背景**：所有组件都在面板里调（系统配置页不再管这两项，避免两边互相覆盖）；
  落桌核对到新实例 id 后写到**这个实例**上（配置一律按 appWidgetId 存）。
- **已落桌实例可编辑**：画廊卡右端的「＋」换成「编辑」，进的是同一套面板 —— 尺寸定死在该实例的
  形态（不再翻页）、底部按钮换成「保存」，保存时把背景 / 不透明度（以及账本 / 配色）四项整体
  写回该 `appWidgetId`（null = 回到默认）。同组件摆了多份时先列实例选一个（每行用背景色点 +
  尺寸 + 不透明度帮认），选完再进面板。
- 预览一律**真比例**：全目录共用一个缩放系数（以最大卡 4×3 为基准），并且**不超过 1:1**——
  画廊卡的灰底托（`PREVIEW_HEIGHT` 126dp，按「4×3 恰好吃满」反推）就是卡身，面板大预览
  直接浮在白底上、按桌面真实尺寸（340×268dp）摆，四周留白对齐各家全高面板——1×1 是小方块、
  2×1 是矮条，相对大小等于桌面占格比例，不随屏幕密度变。widget 再抬一层**柔影**
  （`PREVIEW_SHADOW` 垫底托时用 / `FLOATING_SHADOW` 浮空时用，也乘缩放系数、轮廓按
  `widget_card_round` 的圆角（`@dimen/widget_card_radius`，28dp）等比缩）；底托内边距 10dp 就是留给这层影的余量，别再压小。
  半透明档的柔影按卡底 alpha 同比淡出（真机没有投影，别让低档位剩一圈比卡身还实的"假边"）。
  不透明度 < 100% 时，卡**圆角内**还会垫一层中性示例壁纸（`PREVIEW_WALLPAPER_LIGHT/DARK`）：
  预览页底色是平的，白卡半透明后会和页面底融成一片、卡边"消失"，而里面的色砖 / 文字还在，
  看起来就是「边框和内部不一致」。系统小组件选择器和各家启动器都是把预览压在壁纸上，
  这里用中性示例壁纸代替（组件与桌面壁纸解耦，读不到真实壁纸）。**只在卡内**，不是卡外那圈
  底托——底托会让组件看着多一层背景（已否）；100% 时被卡底完全盖住，等于没有这一层。
  尺寸用**格数**标注（`3×2`），与系统选择器的 `targetCellWidth/Height` 同一口径；这两条与主流 ROM
  的选择器一致，别改成各自拉满。
- 组件命名与说明的口径（对齐系统小部件规范，图标 / 文案审核都看这两条）：名称 2–10 个汉字
  （现用 4 字，如「待办清单」），说明 ≤22 字符（现 11–13 字）；组件内容还要避开系统裁剪的
  圆角与安全区（系统口径：平滑圆角 55px、安全区 ≥42px）。
- `WidgetPin`（`requestPinAppWidget`）走启动器 pin 通道，结果以「桌面上有没有多出新实例」核对（5×1.5s，
  顺带带回新实例 id 供写不透明度 / 背景），成功才报成功。
- **预览图分层产出**：`widget_preview_x.png` 是内容层（文字 / 图标 / 进度值，实色），
  `widget_preview_x_surface.png` 是面板层（跟不透明度淡出的中性底），
  `widget_preview_x_blocks.png` 是色砖层（概览四块砖 / 快捷入口四格，颜色由色族给，跟不透明度淡出；
  只有这三种形态有这一层）。默认卡底时预览按「卡底 → 色砖 × alpha → 面板 × alpha → 内容层」，
  最低档位也能和真机对上；接管了背景 / 不透明度 < 100% 时面板层改当**白模**：只借它的 alpha，
  按卡底明暗 tint 成极淡白 / 黑，再按固定 6% 叠在卡底上（与真机 `WidgetToneSweep` 的卡片相对
  方案同源）。分层判定与真机扫色共用 `WidgetToneSweep.isSurface`（预览布局同样要带 id）。
  `_chip` 是胶囊底（深色卡上要翻白的那类，单独一层才能随卡色反转）；`_card` 是**带卡底的整卡图**，
  只给系统选择器的 `android:previewImage` 用（内容层没有卡底，直接当选器图就是「漂浮的文字」）。
  各层由 `WidgetPreviewPngGenerator` 离屏渲染重出（`WIDGET_PREVIEWS=1` 手动触发）；层名是运行时
  拼的，靠 `res/raw/keep.xml` 的 `tools:keep` 过 R8 资源压缩。改布局 / 生成器后必须重出并同步
  `drawable-nodpi` / `drawable-night-nodpi`（亮暗各 23 内容 + 23 面板 + 3 色砖）。
  带颜色的 `ForegroundColorSpan` 不受 `setTextColor` 控制，出图时必须连 span 一起抹（生成器的
  `hideText`），否则那几行字会漏进面板层。
- 桌面直接操作：待办勾选、打卡签到由广播 Receiver 就地完成。

## 数据口径

- 模板枚举经语义身份（`LifeTemplateKind`）与 `getCategoryName` 翻译，不走图标字面量。
- 生日 / 纪念日的农历滚动与提醒、详情页共用同一口径（`nextYearlyOccurrence`）；概览倒数卡与计数组件共用同一个农历开关解析（`fieldsDataLunarFlag`）。
- 「还剩几天」一律自然日（`DateUtils`），毫秒除法会在当天判错。
