PalmNote 小组件 · 设计交付规范 v37

本文是 PalmNote 小组件（Android 原生 RemoteViews，非 Glance）的设计交付规范：10 个族的全量矩阵设计（4×4 / 4×2 / 2×2 / 4×1）、设计 Token、夜间适配，以及落地时必须遵守的平台约束。

基准视口 1px = 1dp。稿上的 340×148 / 340×340 是理想渲染尺寸，不是单元格声明——Provider 的 minWidth / minHeight 必须按官方公式换算，见 §04.1。

依据：本文全部数值与约束以 Android 官方小组件规范为准——尺寸公式 min = 70n − 30、targetCellWidth/Height（Android 12+）、系统圆角 system_app_widget_background_radius、previewImage 与 previewLayout 的取舍、RemoteViews 支持范围、刷新间隔下限。 不做任何第三方桌面的特殊适配；各家桌面若有额外行为，以平台文档为准。

04给 Agent 的落地技术规范

针对 Android 原生 RemoteViews（非 Glance） 实现的硬性约束。请 Agent 严格遵循，避免踩坑。

1. 尺寸声明 (appwidget-provider XML)

稿上的 340×340 / 340×148 是理想渲染尺寸，不能填进 minWidth / minHeight：这两个值表达的是「需要几格」，不是「我要画多宽」。
按官方公式 min = 70 × n − 30（1 格 40dp / 2 格 110dp / 3 格 180dp / 4 格 250dp）。Android 12+ 由 targetCell 决定格数，min 只作兼容兜底；Android 8–11 的启动器仍按 (min + 30) / 70 反推，给大了会多占一格。
4×4 尺寸
targetCellWidth="4" targetCellHeight="4" minWidth="250dp" minHeight="250dp" minResizeWidth="250dp" minResizeHeight="220dp" resizeMode="horizontal|vertical"
4×2 尺寸
targetCellWidth="4" targetCellHeight="2" minWidth="250dp" minHeight="110dp" minResizeWidth="110dp" minResizeHeight="74dp" resizeMode="horizontal|vertical"
2×2 尺寸
targetCellWidth="2" targetCellHeight="2" minWidth="110dp" minHeight="110dp" minResizeWidth="110dp" minResizeHeight="74dp" resizeMode="horizontal|vertical"
4×1 尺寸
targetCellWidth="4" targetCellHeight="1" minWidth="250dp" minHeight="40dp" minResizeWidth="110dp" minResizeHeight="74dp" resizeMode="horizontal|vertical"
minResize 边界
不得低于各档最小可渲染尺寸：单行档 74dp（再小单行布局会挤爆）、4×4 竖向 220dp（= TALL 阈值，再小就退化成横条构图）、4×4 横向 250dp（不许压到 2 列，否则 12 格网格塞进 160dp）。
预览声明
previewImage 必填；previewLayout 绝不可指向真机布局（12+ 启动器优先用它，静态 inflate 没有数值、也没有运行时着色）——要么不写，要么给静态 *_preview.xml。
可重配
有 android:configure 的必须同时声明 android:widgetFeatures="reconfigurable"，否则 12+ 长按菜单里没有「编辑」入口。
刷新
updatePeriodMillis="1800000"（系统下限 30 分钟）；纯静态组件（快捷入口）写 0。

2. RemoteViews 白名单与禁止项

允许使用
FrameLayout / LinearLayout / RelativeLayout / ImageView / TextView / Button / ProgressBar / ListView / GridView / AdapterViewFlipper 等。
严禁使用
自定义 View、CheckBox、Switch、Space、SpannableString、ViewStub（某些机型不支持）、在布局写 android:tint（必须用代码 setColorFilter）。
进度条/分段条
严禁用 setProgressTintList。统一用 ImageView + ClipDrawable + setImageLevel(0~10000) 实现，或者直接切多张 drawable 背景。
勾选态/点阵
禁止用 CheckBox。用两个 ImageView（实心/空心）配合 setViewVisibility 实现切换，或者通过代码 setBackgroundResource 动态换底。
字体样式
所有文字必须显式设置 lineHeight，并设 android:includeFontPadding="false"。主数字加上 android:fontFeatureSettings="tnum"。
样式不可下发
RemoteViews 没有可用的 setTextStyle（setTypeface 收的是 Typeface 对象，setPaintFlags 会连抗锯齿一起覆盖）。稿里「加粗」这类要求只能在布局里写死；运行时区分状态请只改颜色（如柱图轴上的「今天」列）。

3. 夜间模式（必做）

夜间适配一律走资源限定符：颜色令牌与 drawable 在 values-night/ 提供同名覆盖，组件只引用 @color/…。
不要在绑定过程里读系统 uiMode 再动态改色（setTextColor 一类）：RemoteViews 会被宿主缓存复用，动态改色与实际展示状态容易错位，主题切换也未必触发重新绑定；限定符由系统按当前配置解析，不需要额外代码。
需要按数据上色的部分（族色、涨跌方向）不适用限定符，用 setColorFilter 下发具体色值；这类颜色在日/夜两套里都要保证对比度 ≥4.5:1。
卡面夜间底色 #1C1F26；淡底色令牌在 colors.xml 与 values-night/colors.xml 各给一份。

4. 数据与尺寸切换机制

多尺寸下发：Android 12+ 用 RemoteViews(Map<SizeF, RemoteViews>) 构造，一次给出多个候选尺寸，由桌面按当前格子挑选；旧系统退回「横屏 / 竖屏」两参构造。每个形态只需 2~3 个尺寸桶（紧凑 / 标准 / 宽），不必为每种像素组合建一份布局。
数据绑定：柱状图的高度百分比在 HTML 里是内联样式，实际开发时如果高度固定，可以直接在 XML 里写死高度（如 40dp），通过 setImageViewResource 变高低；或把柱状图替换成 12 个空 ImageView，通过代码设定高度比例。
列表滚动：待办/订阅若需滚动，使用 RemoteViewsService 和 RemoteViewsFactory，严禁用普通的 LinearLayout 硬塞几十行数据。
示例数据：本文档各尺寸的示例数据仅用于展示布局（如物品 4×4 为 38 件/12 类，2×2 与 4×2 为 11 件/4 类）。同一 Widget 实例在尺寸间缩放时，必须复用同一数据源，不允许换一套数字。

5. 分段条、网格与等分留白

分段条圆角
禁止在子段上做内圆角——RemoteViews 不能裁剪子 View。子段一律直角，只有容器首尾用圆角 drawable，或直接切一整条背景图（4×1 的物品/订阅条最适合后者）。
网格布局
设计稿里的 CSS grid（物品 3×4、快捷 3×3、4×2 八格、2×2 四格）在 RemoteViews 中只有 API 31+ 的 GridLayout 可直接对应。minSdk 更低时必须用嵌套 LinearLayout + layout_weight 手搭。
等分留白
justify-content:space-evenly 无对应属性，且 Space 在禁用清单里。用空 View + layout_weight="1" 占位，或在父容器用 paddingVertical 均分。
压缩优先级
4×4 按 340×340 排版，但 minHeight 只声明 250dp。空间不足时按序隐藏：① 元信息/副标题 → ② 底部事件第 3、4 行 → ③ 日历条与进度条 → ④ KPI 从 4 个减到 2 个 → ⑤ 柱状图。主数字与标题在任何尺寸下都不隐藏。参考「11. 空白态与压缩态」的 300×250 示例。

6. 触达区（点击热区）

4×4 快捷九宫格
约 96×96dp，达标。
4×2 快捷八宫格
约 73×41dp，高度不足 48dp。整格可点；若必须严格达标，去掉标题行后单格可到约 57dp。
4×2 待办三行

7. 预览图产出与分层

选择器里的图不是「截屏」，是真实布局 + 样例数据的离屏渲染（Robolectric，3 倍密度）。每个形态产出多层，应用内画廊按 cardColor → blocks → surface → chip → content 合成：
内容层 x
文字 / 图标 / 柱图。卡底与胶囊底在这一层被抽掉——应用内画廊由 Compose 按用户所选背景色实时垫底，换背景色预览才能跟着变。
_surface
内层面板（白底 / 淡彩底块），跟卡片不透明度一起淡出。
_blocks
会盖住卡面的语义色砖；多数形态为空，为空时不出图。
_chip
胶囊底（深色卡上翻白的那类），单独一层才能随卡色反转。
_card
整卡图（卡底 + 全部内容），只给系统选择器的 android:previewImage 用；按 2/3 降采样。
审查纪律
必须把各层合成后再评估效果。只看内容层会得出「底色丢了」的错误结论。
样例基准日
= 生成当天（provider 内部 LocalDate.now()）。fixture 若写死日期，跨过午夜就会出现「头部 10/25、近 7 天末柱却是 0」这类自相矛盾。稿里的 10/24 只是排版时的示例日。

8. 柱图的实现约束

柱间留缝
柱与柱之间留 5dp 缝（每根柱左右各 2.5dp 边距）。不留缝时整排会连成一块色带，读不出「几根柱」。
峰值标只一处
每张图只标一个数值。同高的柱取最靠今天的那一根着色与标注，避免出现「3 3 3」这种重复。
标签带等高
数值标不占柱区高度做不到（RemoteViews 没有绝对定位），改为每列固定 14dp 标签带、非峰值列用 INVISIBLE 占位。用 GONE 会让该列柱区变矮，跨列比例失真。
非零保底
数值很小但非 0 时给 2% 保底高度，保证柱头可见；纯 0 不画。
今天列
用族色区分当前时段列，不加粗（见 §04.2「样式不可下发」）。

9. 实现取舍与已知限制

卡片圆角
28dp；Android 12+ 取 system_app_widget_background_radius 跟系统，31 以下回落 28dp。4×1 单档高 74dp，28dp 视觉偏圆，属既定取舍。
尺寸下限
见 §04.1。4×4 竖向不得小于 220dp（低于此值按横条构图渲染），横向不得小于 250dp（否则 12 格网格挤进 2 列）。
生活计数 4×4
计数只存当前值、没有按天历史，因此用可数八点阵表达进度，不画 7 天柱图——不虚构分母是硬约束。
记账 4×4
KPI 只给「收入 / 结余 / 日均」；不显示环比与「剩余天数」，因为快照里没有上月收入，只做一半口径不如不做。
饼状/占比表达
只用分段条（有真实分母）与点阵；不做无分母的装饰性图形。
并列峰值
同高柱只标最靠今天的一根。
选择器预览
previewImage 指向带卡底的 _card 图；previewLayout 只允许静态预览布局，不指向真机布局。
物品 4×2
四列等宽；英文长类名（Stationery 等）会省略号，中文不受影响。
